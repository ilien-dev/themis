# Spec template

```
# <Feature>

## Problem
<who is affected and what goes wrong today>

## Decisions
- <decision> — <reason> (confirmed by the user | assumed)

## Behavior
- <user-visible behavior, one per line, testable>

## Acceptance criteria
- <observable check with the command or step that shows it; must fail today>

## Out of scope
- <what will not be built, so tickets don't grow into it>
```

Keep it to what a fresh session needs to build it correctly. No file paths or code unless a decision depends on them.
